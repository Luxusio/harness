# Product Specs

Product Specs capture durable product intent for behavior future agents and QA
can validate.

Use `doc/harness/product/ui/` for user-visible screens, flows, states,
localization, and interactions.

Use `doc/harness/product/api/` for externally consumed APIs, webhooks,
SDK-facing behavior, request and response schemas, status codes, validation,
and compatibility expectations.

Write short prose first. State the intended observable behavior and include
verification cues that a QA lens or future bug-fix agent can apply without
guessing from implementation details.
