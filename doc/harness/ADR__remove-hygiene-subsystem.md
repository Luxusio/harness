# ADR - Remove the hygiene subsystem

## Status
Accepted — 2026-08-24. User decision during a harness review session.

## Context

The "auto-hygiene" subsystem classified docs under `doc/changes/` and
`doc/common/` as KEEP/REMOVE/REVIEW, archived the REMOVE set via `git mv`, and
auto-applied contract-drift edits inside the `CONTRACTS.md` managed block. It
comprised roughly 1360 lines across four scripts plus a legacy restore wrapper:

| Script | Lines |
| --- | --- |
| `hygiene_scan.py` | 488 |
| `doc_hygiene.py` | 579 |
| `hygiene_followup.py` | 179 |
| `hygiene_restore.py` | 116 |
| `maintain_restore.py` | 17 |

Review found the subsystem was carrying documentation debt out of proportion to
the value it was delivering:

- **Inert in practice.** It ran in observer mode (session 1 of 14), which
  performs no archive writes and no contract edits.
- **The contract described a system that did not exist.** `CONTRACTS.md` C-16
  claimed `When: SessionStart (automatic...)` and
  `Enforced by: hygiene_scan.py (SessionStart hook, after contract_lint --quick)`.
  No hook wired it: `plugin/hooks/hooks.json` SessionStart ran only the banner,
  `verification_gap_check.py`, and `drift_warn.py`, and
  `setup/bootstrap.md` explicitly instructed *not* to add hygiene to
  SessionStart. The real trigger was post-close, from
  `run/self-improvement.md`. Per CONTRACTS §0 this is the "a prose-only rule is
  commentary" failure mode the design invariants warn against.
  (The setup *template* copy of C-16 described the post-close trigger
  correctly; the drift was in the repo's own `CONTRACTS.md`.)
- **A documented kill switch was never implemented.** `plugin/CLAUDE.md` §12
  listed `HARNESS_DISABLE_HYGIENE`; no script referenced it.
- **Blast radius without a beneficiary.** When active it mutates `doc/**` and
  appends to the managed contract block — significant authority for a feature
  no current workflow depended on.

## Decision

Remove the subsystem entirely: scripts, the C-16 contract (in both
`CONTRACTS.md` and the setup template), the `hygiene.yaml` template, the
post-close invocation and its mandatory follow-up-continuation protocol, the
reference documentation, and the dedicated tests.

Rejected alternatives: keeping the scripts while correcting the contract prose,
and merely disabling the post-close invocation. Both preserve the maintenance
burden for a capability nobody uses; either can be reconstructed from history
if the need returns.

## Consequences

- The post-close pipeline no longer schedules doc-cleanup follow-up tasks. The
  `Mandatory Follow-up Continuation` protocol in the run skills, which existed
  solely to service `hygiene_followup.py`, is gone. Retro and learning
  promotion are unaffected.
- Doc accumulation under `doc/changes/` and `doc/common/` is now a manual
  concern. If it becomes painful, prefer an explicit task over reviving
  automatic archiving.
- `contract_lint.py` continues to guard managed-block markers; only the
  hygiene-specific additive-writer authorization in C-11 was withdrawn, leaving
  the maintain skill as the sole managed-block writer.
- Two long-failing tests
  (`test_hygiene_contracts.py::TestDocOutputs`, which asserted
  `doc/harness/hygiene.yaml` exists in this repo even though it is generated by
  setup into consuming repos) are removed along with the feature.

## Name collision — deliberately out of scope

`promote_learnings.py` uses "hygiene" for an unrelated feature: its stale-file
and contradiction audits over `learnings.jsonl`
(`_audit_stale_files`, `_audit_contradictions`, output `[hygiene] stale-file:`).
That feature, `tests/test_promote_learnings_hygiene.py`,
`doc/harness/patterns/auto-maintenance.md`, and the `HARNESS_DISABLE_HYGIENE`
variable that gates it are **retained**. Anyone grepping for "hygiene" after
this ADR will still find them; they are not remnants of the removed subsystem.

Note: `HARNESS_DISABLE_HYGIENE` remains documented but unimplemented in
`promote_learnings.py`. That is a pre-existing gap, untouched here, and worth a
separate fix — either implement the switch or drop the row.

## Restore

`git revert` the removal commit. The deleted scripts, contract text, and tests
are recoverable in full from history; no data migration is involved because the
only runtime state (`.hygiene-last-run`, `.hygiene-observe.log`,
`.hygiene-session-count`) is regenerable and was gitignored.
